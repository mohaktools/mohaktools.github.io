About the Hash Generator

The Hash Generator computes MD5, SHA-1, SHA-256 and SHA-512 digests of whatever text you paste. The same input always produces the same output, and changing a single character produces a completely different result.

A hash is a one-way fingerprint. It is used to check that a file arrived intact, to compare large values quickly, and to store passwords in a form that cannot simply be read back. The length is fixed per algorithm: 32 hex characters for MD5, 40 for SHA-1, 64 for SHA-256 and 128 for SHA-512.

MD5 and SHA-1 are broken for security purposes: practical collisions have been demonstrated for both, so they should not be used to prove authenticity. SHA-256 is the sensible default. For storing passwords, even SHA-256 is the wrong tool, because it is fast; a salted, deliberately slow algorithm such as bcrypt, scrypt or Argon2 is what you want.

Frequently Asked Questions

Can a hash be reversed?

No, not by design. You can only try inputs and compare. Weak passwords are found by guessing, not by decryption.

Which algorithm should I use?

SHA-256 for integrity checks and general use. MD5 and SHA-1 are fine for checksums but not for security.

Why do the same words give different hashes?

Whitespace and line endings count. A trailing space or a carriage return changes the digest completely.

Can I hash a file?

This tool hashes text. For a file, use sha256sum on the command line or your platform's checksum utility.

Should I hash passwords with this?

No. Fast hashes are easy to brute-force. Use bcrypt, scrypt or Argon2 with a salt.

Is the text sent anywhere?

No. The digest is computed in your browser.
